# SEO + GEO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the React/Vite project into a public technical case study at `/` with SEO/GEO assets while preserving the KYB demo under `/app` and preventing operational pages from indexing.

**Architecture:** Keep React + Vite. Introduce a public `LandingPage`, move the current product layout under `/app`, add a small metadata component driven by route-level configuration, and add static crawl/GEO assets plus a Node-based SEO validator. Legacy operational URLs redirect to the new `/app/**` routes.

**Tech Stack:** React 19, React Router 7, TypeScript 6, Vite 8, Tailwind CSS 4, Node.js built-in modules.

**Spec:** `docs/superpowers/specs/2026-09-13-seo-geo-design.md`

## Global Constraints

- The project is a technical test / demonstrative case study, not a production SaaS product.
- Do not add fabricated customers, metrics, certifications, official SAT affiliation, or production-readiness claims.
- Keep React/Vite; do not migrate frameworks.
- `/` is public and indexable.
- `/app/**` is operational and must use `noindex, nofollow`.
- Sitemap must never contain operational routes or dynamic case IDs.
- Default canonical origin is `https://kyb-customs-platform.vercel.app`, overridable with `VITE_SITE_URL`.
- Author attribution is explicit: Luis Enrique Góngora Ek.
- Avoid adding a large metadata/testing dependency when platform APIs and Node tooling are sufficient.

### Task 1: Add SEO validation test harness

**Files:**
- Create: `frontend/scripts/seo-check.test.mjs`
- Create: `frontend/scripts/seo-check.mjs`
- Modify: `frontend/package.json`

**Interfaces:**
- Produces: `validateSeoFiles(rootDir): string[]`; empty array means valid, otherwise array contains actionable validation failures.
- Produces npm commands: `npm run test:seo` and `npm run seo:check`.

- [ ] **Step 1: Write the failing test**

Create `frontend/scripts/seo-check.test.mjs` using `node:test`, `node:assert/strict`, temporary directories, and fixtures that intentionally omit `llms.txt` and include `/app` in a sitemap. The test must assert that `validateSeoFiles()` reports both failures.

```js
import test from "node:test";
import assert from "node:assert/strict";
import { mkdtemp, mkdir, writeFile } from "node:fs/promises";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { validateSeoFiles } from "./seo-check.mjs";

test("reports missing GEO assets and private routes in sitemap", async () => {
  const root = await mkdtemp(join(tmpdir(), "kyb-seo-"));
  await mkdir(join(root, "public"));
  await writeFile(join(root, "index.html"), '<html lang="es-MX"><head><title>KYB</title><meta name="description" content="demo"><link rel="canonical" href="https://kyb-customs-platform.vercel.app/" /></head></html>');
  await writeFile(join(root, "public", "robots.txt"), "User-agent: *\nAllow: /\nDisallow: /app/\n");
  await writeFile(join(root, "public", "sitemap.xml"), "<urlset><url><loc>https://kyb-customs-platform.vercel.app/app</loc></url></urlset>");
  const failures = await validateSeoFiles(root);
  assert.ok(failures.some((message) => message.includes("llms.txt")));
  assert.ok(failures.some((message) => message.includes("/app")));
});
```
